| ID | Severity | Area | Issue | What breaks |
| --- | --- | --- | --- | --- |
| F1 | Blocker | Contract | LLM-only registration cannot be served | The wizard defaults cache and guard off and requires only the chat model and key. `cache_api` stores empty `embedd_model` and `embedd_key`. Every gateway completion calls `GET /cache` and rejects a config with no embedding model or key, so the project key the UI just showed returns 502. |
| F2 | Blocker | Auth | Every user in the Casdoor org shares one tenant | Identity is `owner` plus `org_name`. Casdoor puts the organization in `owner` and the username in `name`. The code never reads `name` or `id`, so `/cache/mine`, edit, and read are org-wide. One user can open and overwrite another user's provider keys. |
| F3 | Blocker | Auth | Project key alone returns provider credentials | The gateway sends `X-Service-Key` so a leaked client key cannot pull model keys. `GET /cache` ignores that header and returns `model_api_key`, `embed_api_key`, the extractor key, and the guard block. The UI gives that same project key to the end user. `GET /cache/key` checks the service key, and the gateway does not call it. |
| F4 | Blocker | Deploy | Production schema and readiness are incomplete | The only migration adds `cacheconfig.enabled`. It does not create tables. Startup runs `create_all` only when `SC_ENVIRONMENT=development`. An empty Postgres plus `alembic upgrade head` fails. `/health` always returns 200, including when Postgres is down, so a Kubernetes readiness probe on it will route traffic to a pod that cannot serve. |
| F5 | High | Auth | Guard and extractor secrets are stored in plaintext | `llm_key` and `embedd_key` use Fernet. `guard.embed_api_key` and `guard.judge_api_key` are stored in a JSON column, and `extaractor_key` is a plain string. A database backup exposes them. `GET /cache/mine` also returns those values to the browser. |
| F6 | High | Guard | A flag decision disappears on a cache hit | The guard runs before lookup, and a block still returns immediately. A flag sets `guard_flag`, then a hit returns the cached completion with no `guardrail` body and no `x-guardrail` header. Only a miss attaches the flag. |
| F7 | High | Guard | Saved guard and key changes stay stale | Each gateway pod caches the APP config in memory (default TTL 60s) and nothing invalidates it when the UI saves. Disabling a guard, tightening a policy, or rotating a provider key keeps the old behavior until the TTL expires, independently on every replica. |
| F8 | Medium | Cache | Invalid cache numbers are accepted, then fail live | The UI checks that fuzzy distance and similarity are non-empty. The gateway requires fuzzy distance 1–3 and similarity in 0..1. Register returns 201. The first cached chat returns 502 `Config from APP is invalid`. |
| F9 | Medium | Cache | Default `cache_mode` list contains `off` | The stored default is `[off, exact, bm25, fuzzy, semantic]`. The gateway rejects any list that contains `off`. The UI sends a list without `off`, so the wizard path is safe. A row created without an explicit mode list 502s while caching is enabled. |
| F10 | Medium | Contract | Saving an edit with a blank key erases the stored key | Update skips `None` and writes an empty string. The edit form allows a blank API key. Clearing the password field and saving replaces `llm_key` or `embedd_key` with empty. |
| F11 | Medium | Deploy | Embeddings proxy uses the chat base URL | `SC_EMBED_BASE_URL` in `cache_api` is read from `SC_LLM_BASE_URL`. `POST /cache/proxy/embeddings` calls the chat host. The gateway's own `SC_EMBED_BASE_URL` is separate and is the path real chat traffic uses. |
| F12 | Medium | Guard | A guard configured while the switch is off is not stored | `enabled: false` makes `resolve_guard` return `None`, and register then stores no policy and no guard settings. A later edit loads defaults. Turning the guard off on an existing row keeps the policy; creating it off does not. |
